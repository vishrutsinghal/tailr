# TailTrail Test Lab — Presenter Playbook

Use `TAILTRAIL-DEMO-PROMPTS.md` as the copy/paste script. This playbook keeps a
live demo controlled, honest, and recoverable.

## Before presenting

1. Open the exact `TailTrail_Test` root in a new Codex, Copilot, or Claude task.
2. Install/update the Extended profile for the active host.
3. Run `hello tailtrail`; confirm the fenced ASCII banner is aligned.
4. Run host `verify` and `doctor`, `tailtrail presentation conformance`, and
   `tailtrail mcp doctor`.
5. Use a fresh clone or archive completed demo runs. Auto-resolution intentionally
   fails when multiple eligible runs exist.
6. Never apply Terraform or claim external evidence without a linked receipt.

## Recommended 15-minute story

```mermaid
flowchart LR
    H["Hello + readiness"] --> P["Quick / Guided / Expert"]
    P --> S["Start one real fix"]
    S --> D["Discuss"]
    D --> A["Approve"]
    A --> C["Continue + factual evidence"]
    C --> R["Completion Report"]
```

| Minute | Prompts | Proof |
| ---: | --- | --- |
| 0–2 | 1–2 | correct project, adapter, payload, banner |
| 2–5 | 3–6 | three display depths; one canonical authority |
| 5–11 | 7–10 | no-ID six-verb orchestration and focused implementation |
| 11–13 | 11 | evidence-backed closure and acceptance choices |
| 13–15 | 30–31 | honest evidence gap, tokens, evaluation, Learning V3 |

## Full capability route

- Levels 1–3: onboarding, presentation, and daily flow.
- Level 4: Off/Lite/official Standard/official Full AIDLC.
- Level 5: Requirement Completion, Architecture, Behaviour, Maintainability,
  UI, Evidence-Aware and Higher-Tier Testing.
- Levels 6–7: plan discussion, challenge, revision, Program Delivery, Intent
  Bridge.
- Level 8: failure, Debug Harness, bounded correction, Safe Git Recovery.
- Level 9: Durable Workflow Runtime, MCP, Codex/Copilot/Claude parity.
- Levels 10–12: closure, tokens, evaluation, learning, enterprise, negative
  assurance, Product Maturity, and Adoption Validation.

## Presenter recovery

- Wrong folder or stale host instructions: stop, reopen the exact project root,
  and start a new host task.
- Multiple active runs: show the fail-closed candidate list, then provide the
  exact selected ID or archive completed runs.
- Missing evidence: keep the real `evidence-incomplete` report; do not narrate
  success.
- Seeded failure: state that it is deliberate and distinguish it from TailTrail
  installation health.
- Uncommitted valuable work: use task-scoped recovery only; never broad reset.
